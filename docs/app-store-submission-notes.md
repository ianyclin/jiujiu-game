# App Store 第一次送審的經驗（九九流星隊，2026-11-17 送出）

給之後要送審的專案（或其他 session）參考。這份只記「實際遇到、文件上沒寫或寫錯的事」；完整步驟在 `docs/launch-easy.md`，要貼的文字在 `docs/store-listing.md`。

App Store Connect 在 2026 年秋天改版過，畫面跟舊教學不一樣。下面的欄位名稱是繁體中文介面當時的寫法。

## 送審前要先通的事

- **付費 App 協議、銀行、稅表三樣都生效**，內購才讀得到商品。銀行審核等了好幾天。
- **內購要在 TestFlight 實際看到價錢**（購買鈕寫「購買 NT$90」）才送審。讀不到商品時審核員會退件。
- **非消耗型內購在 TestFlight 買過就還原不了**：刪掉重裝仍是已購買，價錢不會再出現。審核用截圖要在買之前先截，或用程式另外產生。
- **build 號每次上傳都要加一**；選 build 的清單是打開頁面時讀的，剛上傳的 build 要重新整理頁面才看得到。
- **版本號**：頁面標題寫 1.0 沒關係，往下捲有「版本」欄，選了 build 會跟著變。

## 填資料時踩到的

- **名稱在整個 App Store 不能重複**。一度以為日文名稱撞名，其實是把副標題貼到名稱欄。
- **遊戲的子類別已經沒有「教育」**，選了「家庭遊戲」。
- **「內容版權」不是填 © 的地方**，是問有沒有用第三方內容（用了 OFL 字型，選「是，且有權使用」）。`© 年份 名字` 填在版本頁的「版權」欄，不用自己打 ©。
- **年齡分級問卷**共七步，全部答「無／否」；最後一步「年齡類別與分級覆蓋」選「專為兒童製作」＋年齡層（核准後不能改）。「分級保護控制」答否（家長關卡只擋購買和外部連結，不算）。
- **每種語言各填一次**：名稱、副標題、隱私權政策網址（在「App 資訊」頁）、宣傳文字、描述、關鍵字、支援 URL、截圖。**只填一次**：版權、版本、審查資訊、發佈方式、build。
  - 隱私權政策網址每種語言都要填，漏了會擋住送出。
- **App 審查資訊**：沒有帳號就把「需要登入」取消；備註用英文寫怎麼過家長關卡、怎麼走到購買畫面。
- **Game Center** 不勾。
- **版本發佈**選「手動發佈」，通過後自己按上架。

## 截圖與素材

- 「配備動態島的 iPhone」那格收 1206 × 2622（6.3 吋），**不收 6.9 吋**的 1320 × 2868。
- iPad 13 吋 2064 × 2752。
- iPhone Duo 一格收外螢幕 1398 × 2034 或內螢幕 2007 × 2853，上限 10 張，只傳了內螢幕那組。
- 英文、日文沒傳截圖時，會沿用主要語言那組（預覽裡看得到）。
- 截圖要讓每個主要玩法都出現；搜尋結果只顯示前三張。
- **「標題和搜尋結果」素材是選填**。通用尺寸 5244 × 2950（不透明 PNG），或標題 3840 × 1646、搜尋結果 3840 × 2560 各一張。上傳後用「預覽」看兩種裁切。用程式拼的圖沒有設計感，最後是用 ChatGPT 生成 3D 劇照風。**不要把遊戲裡的隱藏內容畫上去。**
- App 預覽（影片）選填，沒做。

## 送出時最大的坑：內購沒跟著送

- 在版本頁按「新增以供審查」→ 提交，**只會送出 App 版本**，內購還停在「準備提交」。第一個內購一定要跟 App 版本同一份提交。
- 正確做法：先到「App 內購買項目」點進商品，按「新增以供審查」（會開一份提交草稿，但單獨不能送）；再到版本頁按「新增以供審查」，**選已經存在的那份草稿**，不要選「建立新提交項目」。草稿裡要看到兩項才按提交。
- 送錯了可以在「App 審查」裡「取消提交」，填的資料都會留著。

## 隱私權政策放哪裡

- App 裡的隱私權連結要重新送審才能改，所以網址要放在自己控制得住的地方。原本放 GitHub Pages，免費帳號的 repo 一改 private 就消失。
- 後來用自己的網域＋Cloudflare Pages，只發布 `privacy/` 和 `support/` 兩個資料夾。在 Cloudflare 建立時要選「Continue to Pages」（舊流程），不是上面的 Workers 流程。

## 多個 session 一起做時

- 本機 session 在使用者的電腦上開了分支沒切回 main，使用者照文件 `git pull` 就失敗。做完事要切回 main。
- `git stash` 會把 Xcode 選的 Team 收走，只拿素材時不需要：直接 `git switch main && git pull`。只有遠端也改了 `project.pbxproj`（例如改 build 號）、`git pull` 被擋下來時才需要 stash，之後在 Xcode 重選 Team。
- 文字的唯一來源放在一個檔（這裡是 `store/listing.json`），改了就重新產生文件，使用者永遠從同一個網址複製。
